# Retailor frontend

Next App Router/React application with an animated landing, one-workspace photo/review/setup flow, live Tailor preview, generated storefront and shared owner dashboard. Thirty-six curated looks share real clothing/photos and exact commerce rules. Local provider output is declared fixture behavior; paid/hosted/owner acceptance remains separate.

RTL-104 keeps both sample and personal selection to individual photo previews and local file checks, with replace/remove and no upload grouping controls. **Create product draft** deliberately starts recognition and suggested grouping. Product draft review owns Link photos / Separate photo and editing before Personalize. Existing reviewed groups, byte witnesses, restore/rebuild/cancel/reset and photo-required controls remain; selection never dispatches recognition. [Current photo flow](../../docs/design/PHOTO-LINKING.md).

RTL-105 gives `/` a full-viewport, centered video hero. Transparent white navigation becomes white/navy at the real hero boundary; the lime CTA stays visible. The decorative local H.264 loop is 16 seconds, 1440×900/24fps, silent, 2.46 MiB, with a 74 KiB matching WebP poster. Latest owner feedback removes the eyebrow/dot and all visible playback controls; native muted inline autoplay/loop remains. A navy background/poster keeps the real HTML copy usable if playback is unavailable. No OS-based motion suppression, remote footage or runtime encoder is used. Other storefront/dashboard branding is unchanged.

Phone/tablet use a centered “Swipe up to see details” cue with a quiet upward finger-swipe animation and touch-hand icon instead of the desktop arrow. There is no mouse outline. It remains a normal tappable/keyboard-accessible link to How it works, reusing smooth scrolling and focus. Native vertical swiping is not intercepted. The cue appears through 1100px and on coarse touch-only pointers; wide desktop keeps the arrow.

`public/landing/hero-provenance.json` identifies the six existing generated demo photos and their exact source hashes. Regenerate offline with `node scripts/media/render-landing-hero.mjs <absolute-ffmpeg-executable> <absolute-@napi-rs/canvas-index.js>` using FFmpeg with libx264 and the desktop's bundled canvas library (or an operator-supplied local installation). The renderer has a fixed 16-second/frame/dimension budget, encoder deadline and 4 MiB media cap; scratch output stays ignored under `artifacts/local/RTL-105/render`. It needs no provider key, network, new app dependency or visitor data. Both media files and provenance are explicitly packaged/fingerprinted; encoder binaries are never shipped.

From repository root run `pnpm dev:frontend` in its own terminal after `pnpm dev:backend` is healthy on 4311. Frontend uses dedicated [4310](http://127.0.0.1:4310). The launcher refuses occupied ports, never selects another port or terminates another process. Ctrl+C stops the owned launcher/child; verify ownership before any further stop. Ignored app-local `.env.local` loads through the normal launcher; `.env.example` has safe values. Development forces fake/paid-off inherited flags without changing the parent. After `pnpm build`, `pnpm start:frontend` preserves normal explicit configuration. Development `.next-dev` and production `.next` are separate.

Canonical routes are `/` (landing) and `/demo` (temporary workspace). `/design` is a dev reference gated by the launcher flag and unavailable under production/start; it is not owner design approval. Browser APIs are relative `/api/retailor/v1/...`. Private backend origin/audience/identity stay in server modules with no `NEXT_PUBLIC_*` exposure. The bridge accepts fixed route/method operations, bounds transport slots/bytes, validates write origins, strips client auth and propagates deadlines. Identity uses the fixed Cloud Run metadata endpoint with the owned AbortSignal; no downloaded service-account key. Action admission is additional to platform IAM.

The Dockerfile uses a workspace tracing root, Next standalone server, traced modules, static chunks and approved photos/fonts/licences. UID 1000 runs Node directly on `HOSTNAME=0.0.0.0` and supplied `PORT` (default 4310). No app-local env, runtime installer or development preview photos are included. Linux checks deny networking and publish no host port. Next 16.4 completes cleanup then deliberately exits 143 on SIGTERM. See the [release packet](../../docs/operations/RELEASE.md) and [Linux evidence](../../docs/validation/RTL-021.md).

Focused bridge checks: `pnpm exec vitest run apps/frontend/src/server/bridge.test.ts`. Root `pnpm check` is unpaid, network-isolated and never deploys. Build success does not prove appearance, IAM, live results or hosted capacity. [RTL-019](../../docs/validation/RTL-019.md) records actual local responsive/keyboard/design observations and their physical-device/owner limitations.

RTL-023 prepares public origin protection through `RETAILOR_ORIGIN_GUARD=cloudflare` and a private 32-byte lowercase-hex `RETAILOR_ORIGIN_SECRET`, supplied only through approved runtime secret configuration. A trusted Cloudflare transform must overwrite `x-retailor-origin`; never expose/forward/log this seal. Pages/RSC/static/assets use Proxy, while the fixed API checks inside the existing bridge to preserve 19-MiB streaming uploads. Other Proxy bodies are capped at 16 KiB. Enabled missing/invalid config fails closed with friendly errors; dev/restricted defaults stay unchanged. Guarded startup is TCP with no public health exemption. Future API/server-action changes must retain coverage and streaming bounds. Actual edge/rate/all-URL/normal-flow and account proof remain separate release gates in the [manual packet](../../docs/operations/RELEASE.md#rtl-023-public-origin-and-spend-gates).
