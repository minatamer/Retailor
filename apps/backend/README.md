# Retailor backend

RTL-102 makes logos a first-class local feature in every app mode. Bundled fonts/marks use no AI image API. Live/production retains existing Turnstile/signing prerequisites and exact-context cookie/grant, count/rate/deadline and shared concurrency protections, independently of the AI paid master/OpenAI key. Catalogue/Tailor remain paid-gated AI; production fixtures stay prohibited. [Current logo policy](../../docs/engineering/LOGOS.md) supersedes historical AI-logo descriptions below.

Express factory and bounded provider runtime. Config/runtime/factory imports are inert: no environment loading, listener or external request. `src/server.ts` explicitly loads only app-local `.env.local`, parses config and starts the owned listener. No order/catalogue CRUD database or upload directory exists; commerce mutations happen in the browser session graph.

From repository root run `pnpm dev:backend` in its own terminal, then `pnpm dev:frontend` in another. Backend uses dedicated **4311** and refuses occupied listeners. No key/env file is required for fake development. Ignored `.env.local` is optional; `.env.example` has blank secrets/safe defaults. Dev forces development/fake/paid-off inherited flags without changing the parent. After `pnpm build`, `pnpm start:backend` runs compiled ESM and preserves explicit normal config. Ctrl+C shuts down only the owned server/launcher; never kill a sibling by executable name or port alone.

GET `/v1/health` is content-free liveness; `/v1/ready` reports selected runtime readiness; `/v1/config` exposes safe capabilities. Health/config dispatch no paid request. Fake development supplies declared catalogue/Tailor/logo/FX fixtures. Production rejects fake mode and non-HTTPS frontend origin. Live mode with missing prerequisites remains paid-unavailable (`/ready=503`) and never falls back to fixtures. FX is a separate fixed public reference adapter with bounded reads/cache/deadline. Missing paid keys do not prevent liveness or frontend static operation.

Catalogue, role-bounded Tailor and optional logos use injected ports, exact schemas, origin/challenge/action grants, finite process-local action counters, deadlines and shared two-slot AI admission. Native preparation has two workers/two waiters. HTTP allows four total bodies, two unknown and two per verified issued safety identity; minute capacity is 16 unknown + 48 issued, with 24 per issued identity. Signature/boot/expiry verification precedes classification; cheap invalid headers retain bounded discard, not minute starvation. [Image concurrency](../../docs/engineering/IMAGE-CONCURRENCY.md) retains the research/timings. These are finite process controls, not per-person fairness or a global spending cap; actual edge/account/restart/overlap proof is required.

RTL-024 simplifies configuration to APP_ENV, fake mode, the paid master and required credentials. There is no APP_REVISION, separate live/logo signoff flag, logo-enable flag or process dollar cap. Logos share live AI availability, retaining actual automatic moderation and explicit optional batch approval. Paid-off constructs no live AI provider; token/unknown-usage diagnostics and all rate/grant/concurrency protections remain.

Docker pins Node/pnpm, installs Linux Sharp from the frozen lockfile, compiles public packages/backend and copies pnpm 11's portable production-only deployment. UID 1000 runs `node dist/server.js` directly, binding 0.0.0.0 in production to supplied `PORT` (default 4311). No env secret, app/test source or runtime package manager is copied. SIGTERM closes only the owned server and forces its remaining connections after five seconds. Startup/liveness uses `/v1/health`, never paid readiness. See [release/IAM/secret/rollback instructions](../../docs/operations/RELEASE.md) and [Linux checks](../../docs/validation/RTL-021.md).

Focused injected HTTP checks: `pnpm exec vitest run apps/backend/src/http/app.test.ts`. Root checks are unpaid and network-isolated. Actual account/AI/billing, Linux paid load and hosted IAM/identity require separate accepted evidence; fixtures cannot supply it.

RTL-103 fixes sandbox enablement and the `retailor-511714` / `retailor-511714-checkout-photos` resources in server-only `src/config/checkout.ts`. Only the test-only `STRIPE_API_KEY` remains in backend `.env.local`; a blank key leaves checkout unavailable, and live/malformed keys are rejected. Remove/revoke the key to disable checkout, then restart the backend. Local Google Storage access keeps owner-authenticated impersonated ADC; see [storage/auth setup](../../docs/operations/CHECKOUT-STORAGE.md). Health/config dispatch no storage or Stripe requests. Only deliberate checkout sends sanitized selected derivatives to the private bucket and exact cart/name/options to Stripe. Signed identity, finite create/status/concurrency limits, fixed guarded operations and server-side payment verification remain mandatory. A verified payment return places the connected local demo order once (RTL-097); no real charge or shipment occurs. Attempt authority is process-local: a restart loses pending verification, with safe unchanged-bag recovery and expiry/lifecycle backstops. Real payments and durable fulfilment/webhooks are outside this demo.
