Implementation order: contracts and bounded encrypted storage; injected auth/provider/service; fixed HTTP/bridge integration; meaningful restart/tampering/refresh/contention tests; all six applicable gates; settled read-only review and verified fixes. The frontend session-controller onboarding hooks are integrated in RTL-165, after the backend lifecycle is ready; RTL-162 exposes only the bounded session bootstrap/auth foundation. No product write operation is enabled here.

Dependency restoration uses the existing frozen lockfile, with no package upgrades. Native OAuth and real GCS requests remain unperformed. Local storage is explicitly single-owner; the hosted adapter uses conditional generations, not a volatile fallback.

Local storage decision: Node24's built-in SQLite owns one application-encrypted blob with exclusive OS locking and FULL synchronous commits. It replaces a provisional PID-file approach whose stale-lock takeover could race after a crash. There is no SQLite dependency, SQL service, ORM or merchant table. The OS releases the exclusive lock on process exit; an actual child-process interrupted-write regression proves rollback/reopen. The entire decrypted deployment ledger is capped at2 MiB, stricter than the plan's per-installation ceiling.
