# Connected shopping and simulated orders

RTL-010 local implementation, 12 October 2026, extended by RTL-092/097 on15 October. Shopping is available only in the accepted storefront. Studio, Pulse and Gallery share actual variants, one controller-owned bag and the same order commands. Local ordering uses no real payment, shipment or database. Configured Stripe sandbox checkout now completes that same local demo order after verified test payment.

## Optional Stripe sandbox gateway

RTL-097 replaces the separate gateway card and Place demo order action with one **Checkout** button. A small hover/focus/touch **!** control contains selected-photo/store sharing disclosure,4242/future-expiry/three-digit-CVC guidance and no-real-charge/shipment copy. A transform-only infinite spinner remains mounted through preparation and navigation, with owned cancellation/disposal/deadline cleanup. Connecting/completion banners and the old unverifiable-payment wording are removed; bounded failures keep a short retry message. Default-off configuration still uses the local demo order path. A failed capability read or configured sandbox operation never silently falls back to placement.

The server derives exact USD/EUR line amounts, THREAD10 discount, delivery and any rounding residual through the shared pure commerce authority; it validates graph/stock/photos and actual sanitized selected image bytes. Stripe sees the chosen store name, supported button colour and each selected garment's title/colour/size/quantity/photo. Fixed sandbox keys/results, private signed image reads and guarded server operations apply. [Configuration and limits](../operations/CHECKOUT-STORAGE.md).

The controller persists an attempt and captured order identity before leaving, restoring store/photos/bag/promotion after full-page navigation. Workspace/scenario/revision/currency/photo/brand/expiry witnesses fence stale results. Closing/backing out during preparation aborts it; late known sessions are expired/cleaned without navigation. Concurrent local placement is blocked while preparing. Server status must verify a test-only completed/paid session and the captured amount/currency; a URL claim alone has no effect. The controller recomputes the exact quote and applies traffic activity, shopper draft and place-order commands to a temporary graph. Only a fully successful result publishes graph/stock, bag clearing, saved display scope and bounded attempt→order confirmation together, opening **Order placed** directly. Failure publishes none of the temporary commands. Repeated returns/reloads reopen that receipt. Reopening/reviewing a still-current pending payment preserves its graph revision so temporary verification failure can be retried. Legacy pending attempts without an order identity remain supported.

Per-session `wallet_options[link][display]=never` hides Link's save-information offer, verified against the actual hosted page. Customer save-card/`setup_future_usage` options are not enabled. Explicit `saved_payment_method_options` requires a Stripe Customer and is omitted for this guest flow. The hosted browser-tab title still uses the sandbox account label; the visible merchant name uses the chosen store name. No global branding/payment settings are changed. Primary references: [Stripe's Link display control](https://raw.githubusercontent.com/stripe/stripe-dotnet/master/src/Stripe.net/Services/Checkout/Sessions/SessionWalletOptionsLinkOptions.cs), [Checkout session parameters](https://docs.stripe.com/api/checkout/sessions/create). [Actual RTL-097 API/UI/order evidence](../validation/RTL-097.md).

Backend restart still loses process-local attempt verification authority; failed/unknown verification leaves the local graph intact. Durable server fulfilment/webhooks, real payments and cross-device persistence remain outside this demo. Earlier RTL-092 verify-only evidence is historical and superseded by RTL-097's explicit owner-authorized local fulfilment behavior.

## Bag and availability

Select the actual garment option and one to five units. Adding the same variant merges quantities up to five; the bag holds eight distinct lines. Bag edits reserve no inventory. Every required product photograph must still be validated and available; missing photos, sold-out quantities or archived options block review. Removal is always offered for retained lines. Product deletion/archive commands remove their affected bag lines with an explicit notice and never select another garment.

Rows derive current titles/options/prices/costs/stock/photos from the graph. A stored bag price remains a comparison witness, so an owner price change is disclosed. An over-limit current bag stays editable with an explicit quantity/removal recovery message instead of a thrown rendering error.

The default demo delivery charge is USD 600 cents, tax zero. RTL-076 replaces the fixed USD 500-cent checkbox with a Promo code field. Its grey placeholder suggests `THREAD10`; Apply accepts case/outer-whitespace differences and applies 10% to the actual merchandise subtotal, rounded once to a USD cent using the shared exact rational helper. Delivery and tax are excluded. Invalid codes leave prices unchanged and offer the working code; Remove clears the promotion. Savings recompute with current quantities/prices and use the existing USD/EUR projection and reviewed amount. Promo input state is ephemeral, scoped to workspace/scenario/latest placed order, and a new purchase requires applying the code again. No promotion service or new order authority is added. [Actual RTL-076 validation](../validation/RTL-076.md). Owner lifecycle/register editing belongs to RTL-011.

## Review, placement and currency

Review prepares a bounded local shopper draft with the seeded fictional label **Demo shopper**, actual line IDs/quantities and exact USD totals. There are no real names, addresses, emails or card inputs. Review snapshots the current revision, workspace/scenario, price/stock/cost/photo witness, currency scope and stable place command ID, with a maximum two-minute confirmation lifetime. It deducts no stock.

Checkout's default-off local path checks current availability and the reviewed context again. Revision, options, price/stock/photo/currency changes or review expiry retain the current selections and require review. One unavailable line rejects the whole placement. The pure command writes immutable price/cost/discount-unit snapshots and linked sale movements atomically, then clears the purchased bag. The controller persists that exact graph together with the order ID and its display scope in one projection update. A repeated successful click returns the same order reference; refreshed receipt rendering invokes no command or provider.

USD remains the recorded authority. EUR uses the accepted dated reference for unit prices, line sums, discount, delivery, tax and order total. Displayed unit price × quantity forms each line; the shared exact projection includes any nonzero rounding adjustment so visible components reconcile to the total. Confirmation always uses its recorded placement scope, even after storefront currency changes or quote expiry. A later currency selection cannot rewrite an order.

## Shopper visits and recovery

Accepted-store exploration, product engagement, a populated bag and checkout use existing nested add/touch traffic commands. Styling/design previews and owner actions create no eligible shopper visit. Stages and product IDs are deduplicated; repeated bag clicks create no event stream. Multiple linked orders in one visit contribute one converting session to the shared fact engine.

An exact controller-owned lastActivityAt defines a new visit after 30 minutes of inactivity, within the fixed two-hour workspace. Graph activity timestamps refresh at most once per minute between stage changes; the exact inactivity timestamp is persisted independently. There are at most 20 guest visits, 10 guest orders and the existing bounded receipt/draft limits. Limit errors are shown without deleting older records. The fictional shopper ID is reused for subsequent orders.

Projection recovery restores bag, buyer/visit/draft and latest order references without replaying placement. Checkout review and modal callbacks are ephemeral: refresh requires a new review. Opening an empty bag can show the latest saved receipt; removing the last selection shows the empty bag immediately. Scenario rebuild clears replaced shopping IDs and order-display references. Reset/expiry clears the controller’s owned modal/review state and pending operations; inactive controllers reject effects.
