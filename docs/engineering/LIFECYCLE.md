# Temporary workspace lifecycle

RTL-016 integrates the resource owners introduced by RTL-003 through RTL-015. The single `SessionController` owns business state and coordinates children; there is no second catalogue, commerce or recovery store. Actual local evidence and limitations belong in [RTL-016 validation](../validation/RTL-016.md).

Refresh restores eligible state; pending forms, tours, confirmations and prepared logo requests remain absent. |

## Recovery and interruption

RTL-027 corrects reset entry ordering: remove the retiring session projection before awaiting its scoped photo/cache cleanup. A document interrupted during cleanup must not restore the previous collection. Fresh workspace identity and fixed lifetime still belong to the one session controller. Metadata/cache deletion failures retain their original-expiry warnings, including when persisting the replacement workspace also fails; this is no physical-erasure guarantee.

Deliberate sample selection is idempotent. Already selected, available source hashes matching the verified public sample are not decoded/added again; an available cached but unselected matching photo can be reused through the normal bounded intake path. Manual uploads still report real duplicates, unavailable photo witnesses remain unavailable, and count/byte/concurrency limits remain unchanged. Choosing/reusing sample photos dispatches no model call; every deliberate new public draft still requires its normal fresh live recognition. Actual RTL-027 findings and distinct browser/unit evidence belong in [its validation](../validation/RTL-027.md).

RTL-042 adds bounded disjoint `photoLinks` plus a default-compatible `photoLinksInitialized` boolean to the same allow-listed projection. The photo resource child owns their runtime counterpart. Refresh restores organization without processing; reset/dispose clear it. Link/cover/order and same-ID source-byte changes advance input revision and cancel/fence late interpretation. Review synchronizes links locally without an extra provider request. An explicit sample retry can complete links left unfinished by interrupted intake, while the initialization marker preserves deliberate unlink choices. The sample is now18 verified photos/15 original garments with three alternate views; public interpretation still requires fresh recognition. [UX and recovery precision](../design/PHOTO-LINKING.md).

The strict 2-MiB UTF-8 session projection keeps the independently validated 512-KiB graph, source descriptors, completed interpretation/review, finite designs/setup choices, dated FX, bounded shopping/preferences and at most forty finalized messages. It does not contain Blob bytes/Base64, object URLs, controllers, raw provider output, configuration, challenges or grants. Stored conversation proposals are inert display data; restored messages cannot execute them.

The optional `pendingProvider` field is one finite category (`catalogue`, `assistant`, `logos`) or null. It contains no prompt, grant, operation payload or callback. The live owner sets it during a request. Restore clears it and says the provider outcome may be unknown; it never dispatches a retry. Older version-1 projections without it retain the default null and the original processing-stage interruption check. Version, unknown fields, future dates, graph/photo relationships and exact fixed two-hour lifetime are checked rather than coerced. Recovery preset/FX repairs remain explicit and limited to their existing finite policies.

Refresh recreates verified photo/logo URLs. Missing clothing bytes preserve metadata but block affected publication/purchases and offer exact-original repair. A missing optional logo uses the wordmark. Reset clears notices, forms, history, accepted/preview design, currency, graphs/receipts, candidate state and owned runtime resources before replacing identity. Every late completion remains fenced. Storage/quota failure preserves live in-memory work with an honest warning; cache deletion failure retains its original fixed expiry instead of claiming erasure.

## Local JSON report

`Export JSON` appears after catalogue publication and is a local, unpaid action. The strict `@retailor/contracts/export` version-1 report contains finalized catalogue and photo metadata, historical completed catalogue-review provenance, synthetic posted records, accepted design (null until accepted), selected logo and hero metadata, scenario origin, the selected dashboard period/scope and the exact fact registry with formulas, date basis, numerators/denominators, contributors and exclusions. Dated storefront currency and order-confirmation scopes remain metadata; all authoritative amounts stay USD integer cents.

The report is detached JSON with a 2-MiB UTF-8 cap and `retailor-demo-v1-YYYY-MM-DD.json` filename. It excludes image bytes, complete chat, bag, unposted order/expense drafts, receipts/command identities/Undo payloads, preview forms/design, pending executable proposals, grants, tokens and server configuration. The completed catalogue review is explicitly historical; `records.products` is the current catalogue after owner edits. There is no import/replay editor, ZIP, hosted file library or account.

Reset cannot recall files already saved by the browser or provider input already dispatched. Cancellation does not prove zero billing or deletion of provider copies. Browser close does not promise immediate physical deletion. Native browser viewport observations, deterministic fake-clock/cache tests and actual JSON downloads support different claims; physical devices, paid outcomes and hosted runtimes require their own evidence.
