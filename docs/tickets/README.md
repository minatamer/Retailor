## Selection, dependencies and status

Under the current execution authorization, select the lowest numbered **Planned** packet whose required dependencies actually exist and have the necessary verified local behavior. RTL-001, RTL-004 and RTL-005 are complete; RTL-002, RTL-003, RTL-006, RTL-007, RTL-008 and RTL-009 have verified local completion with separately tracked visual/live/account evidence. **RTL-010** is the next eligible packet. Eligibility does not authorize parallel agents or new chats. Do not claim a dependency passed because a ticket exists, its boxes were edited or a similarly named commit appeared.

A dependency may be locally implemented while a separately named owner-visual, paid or hosted check remains pending. That verified local behavior can support independent local follow-on work, provided pending capabilities stay clearly unavailable and their acceptance remains tracked. Public release must wait for required actual live and hosted evidence. In particular, RTL-021 packaging preparation does not depend on RTL-020's paid run; RTL-022 requires both.

Use these status meanings in the queue and packet together:

| Status | Evidence needed |
| --- | --- |
| Planned — not started | Reviewed scope only; no implementation evidence yet. |
| In progress | Actual authorized implementation is underway; record meaningful completed and remaining work. |
| Implemented locally — external acceptance pending | Required local behavior/checks exist at a named snapshot; each unperformed visual/live/container/hosted check has a concrete prerequisite. |
| Complete | All required acceptance for that packet actually passes; evidence identifies the revision/environment and any explicit non-blocking limits. |

Optional visitor actions still have required implementation contracts: logo generation may be skipped during the demo, but the post-style offer, safe admission and wordmark recovery must exist. A genuinely unavailable optional external capability may remain disabled with a clear limitation; do not claim it worked. RTL-020 and RTL-022 must distinguish required live release blockers from optional unavailable paths.
