## Problem and result

The user's promise is temporary remote demo products. Browser unload and an in-memory connection cannot deliver it. Build durable exact-owned deletion and a bounded cleanup service that runs without the browser, survives backend restart and reports failure honestly. Product removal and uninstall are separate; cleanup must finish before access is revoked. Never delete a preexisting merchant product or another session's artifact.

## Implementation contract

1. Support selected owned-product removal while staying connected and whole-session cleanup for Disconnect, reset and original two-hour expiry. Stop new writes and fence generations before changing state. Persist intent before acknowledging it. Settle/reconcile in-flight and unknown creates/updates/media first; late provider completion stays owned by cleanup. Match exact app/shop/session/product IDs and server marker; raw IDs/tags alone cannot authorize deletion.
2. Verify each product deletion result or conclusively already-absent state. Track asynchronous operations and standalone owned media/file objects when applicable; delete reusable files only after verifying no unrelated merchant references, otherwise preserve/report the residual artifact. Partial failure leaves the remaining IDs pending; do not mark the connection cleaned on HTTP 200 or erase ownership before acknowledgement. Do not recreate a merchant-deleted product simply to satisfy a stale export response.
3. Disconnect/reset/expiry clean all owned remote artifacts before uninstall/revocation, then erase credentials and close the installation. Keep selected removal distinct. Unknown uninstall has its own tracked outcome; do not repeat non-idempotent calls without reconciliation. The single unresolved workspace/shop lease prevents one visitor's disconnect from revoking another visitor's active cleanup access.
4. Use the same cleanup service in an explicit local CLI command and a local backend-owned timer, plus an operator-ready private scheduled hosted invocation. The browser need not remain open. Timer startup/shutdown is explicit, imports remain inert and replica leases are durable. Cloud Run scale-to-zero requires the separately configured scheduled invocation; do not advertise hosted expiry cleanup until it actually runs. Keep maintenance authentication separate from visitor sessions, preserve backend IAM and all public origin seals.
5. Apply named finite limits: one-minute sweep cadence, first-attempt target within two minutes while available, 55-second/40-call/ten-installation sweep cap, per-shop serialization and a deployment-wide cap. Persist at most eight cleanup attempts/item over 24 hours with explicit bounded backoff/Retry-After; exhausting the budget becomes needs-attention. Reserve cleanup capacity independently of user polling/writes; avoid unbounded scans, hidden export retries or sleeping HTTP requests.
6. Browser reset cannot wait indefinitely for remote cleanup. Acknowledge durable enqueue when possible, detach locally with generation fencing and rely on the original server deadline if offline. Preserve a useful bounded local status/manual-recovery reference where appropriate without putting tokens or a privileged capability in exported reports. Server expiry cannot be extended by reconnect, new browser timestamps or forged workspace labels.
7. Implement exact-topic signed `app/uninstalled`, `customers/data_request`, `customers/redact` and `shop/redact` handlers. Verify bounded raw body/HMAC first, reject invalid HMAC, durably deduplicate deliveries and acknowledge without refreshing a potentially revoked token. Verify actual subscription separately from CLI samples. Protect a new installation from old/duplicate/out-of-order events using a tested installation/event reconciliation rule; do not guess that the payload carries a workspace generation.
8. External uninstall/revoked scopes/lost key/storage outage transitions to truthful pending/needs-attention. Do not promise API deletion after access is lost. Give the visitor exact owned-product manual cleanup guidance; verified reconnection may resume the retained ledger, never adopt arbitrary products. Redaction deletes applicable local data and customer payloads are not retained; the app requests no customer/order scopes.
9. Erase credentials promptly after verified cleanup/uninstall, with a hard 24-hour-after-session-end cutoff; erase unresolved private ownership/manual-recovery metadata by seven days or earlier valid redaction. Bound all deduplication/error metadata. Document that retention cutoff ends automatic recovery and cannot prove provider-side erasure. Keep aggregate private diagnostics content-free.

## Acceptance and meaningful tests

| Case                                                                            | Required result                                                                                                                                 |
| ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Remove one owned product                                                        | Only that product/artifacts removed; connection and unrelated products survive.                                                                 |
| Disconnect/reset/expiry, including zero exported products                       | Durable request; writes fenced; exact cleanup verified before uninstall; credentials erased at the correct point.                               |
| Close browser, restart backend, two runner instances, stale worker lease        | Expiry still discovered from durable state; one authorized worker; no duplicate destructive work or lost ownership.                             |
| Create succeeds after reset/disconnect or times out before ID storage           | Reconcile marker/intent; remote side effect still removed or honestly unresolved.                                                               |
| Partial delete/media/uninstall failures, 429/5xx                                | Separate bounded statuses/attempt budgets; no false success or infinite retry.                                                                  |
| Missing/corrupt storage/key, expired credentials and revoked scopes             | Fail closed for new work; useful fixed status; no token leakage or volatile fallback.                                                           |
| External uninstall and delayed uninstall after reinstall                        | No doomed token refresh in webhook acknowledgement; current installation not incorrectly detached; truthful remote cleanup limitation.          |
| Invalid HMAC, oversized body, duplicate/out-of-order webhook, privacy redaction | No unauthorized mutation; bounded durable processing; applicable records erased without persisting customer payloads.                           |
| Forged IDs/markers/shop, another session, preexisting sentinel product          | No unrelated deletion or read disclosure.                                                                                                       |
| Exact lifetime/attempt/retention/capacity thresholds                            | Server deadline honored; no guest extension, unbounded map or eviction of unresolved active state; cutoff produces documented recovery outcome. |

Use actual local persistent-adapter restart/contention tests and injected network/clock failures, not only mocked successful deletion. Automated tests remain paid-off and network-denied. Native browser-closed expiry, revoked-token behavior, real webhook delivery and hosted scheduler acceptance remain explicitly pending when unavailable.
