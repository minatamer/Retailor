## Correction and permanent policy

RTL-179 asked the browser for native smooth scrolling and verified the endpoint. The owner observed a jump; those endpoint checks were not proof of animated movement. The sample now uses an explicit **800ms cubic ease-out requestAnimationFrame timeline**, sharing the landing page's existing approach through one UI helper. Landing keeps its original450–900ms authored duration and link/hash/focus behavior. No specific OS/browser preference was established as the cause of native scrolling's observed behavior.

Source/config scans across `apps`, `scripts`, `test`, `.github`, and public SVG/CSS/JS/JSON assets found no reduced-motion branch, animation-disable flag or global zero-duration/paused suppression rule. There was no existing app-wide off setting to remove; no machine-wide preference was changed. `AGENTS.md` permanently retains the no-animation-off/no-OS-suppression policy and adds explicit frame-animation/intermediate-position evidence for authored scrolling that must visibly animate.

The helper owns one pending frame/cancel function per mounted owner, cancels replacement/input/navigation/pagehide/resize/unmount, ignores cancelled late frames, clamps duration to450–1200ms and defaults nonfinite durations to800ms. Zero cannot disable animation. Per-frame `scrollTo(...behavior:"instant")` writes the interpolated position without nesting a second browser animation; the frame timeline supplies visible movement. No API, environment, credential, controller/business state or dependency change.
