## Diagnosis and delivered behavior

The old examples did map to Studio/Pulse/Gallery, but all three used the compact marketing mode inside narrow 310-pixel-high cards. That mode hides copy, actions, category entrances, featured products, tools and footer, and overrides the family layouts. It therefore did not demonstrate the complete stores well. Its non-wrapping header also allowed the wordmark flex item to shrink, causing the screenshot's stacked FORME letters.

- A new local `StoreFamilies` component uses three finite layout buttons and Home/Collection/Product buttons to drive one wide, bounded, labelled preview. Descriptions come from the existing template registry, designs/photos/products from the existing authored illustration. Both selected states are visible and expose `aria-pressed`/`aria-controls`.
- The existing `StoreIllustration` supports explicit compact/full presentation. Full uses the actual storefront CSS and complete renderer, not a new mockup or alternate store. Both modes retain the same inert/aria-hidden illustration boundary and suppress the real store's outer focus/scroll effect. The normal store continues to omit the illustration value and retains the same full styling, actions, data and contracts.
- Compact-only rules now target `data-illustration="compact"`; the existing full responsive rules include full illustrations. Hero compact remains the default. Only compact wordmark shrink/wrap behavior is corrected. Motion, timers, offscreen work and failed-photo state/handlers remain unchanged.
- The full preview scrolls natively at 640 pixels high (560 on phones). Its focusable labelled region has visible focus and ordinary Tab escape. Layout/page changes reset only its owned scroll, preserve the selected page across layout changes and keep focus on the selected control. No timer, visitor storage, workspace/controller, provider, money or actual store action is added. The same illustrative jeans and $68.00 appear throughout.
- Old family card-only CSS was removed after its sole landing consumer was replaced. Previous merged owner/FAQ and customer/owner Tailor sections remain intact. Landing design documentation records the actual revised presentation and illustration boundary.
