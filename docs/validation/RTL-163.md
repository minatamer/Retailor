## Media decision and explicit limitations

Uploads use the existing bounded sanitizer and direct Shopify staging; upload requests carry no Admin API token. No Retailor-hosted image object exists to leak or clean. Product deletion is the owned media cleanup path; no separately reusable File is created by application code. Shopify documents that deletion preserves media now referenced by another product. Staging expiry, native Files behavior/scopes and physical retention remain provider-owned/unverified until native acceptance. Application code cannot delete an unused Shopify staging reservation or force its TTL; the original plan's application-controlled staging erasure target is therefore **not claimed**. Native acceptance must prove this path needs no additional file scope/artifact cleanup before live writes are accepted.

Image changes on an existing export require explicit Remove then a fresh Export; Update rejects a changed image set rather than silently ignoring it or introducing unverified reusable-file deletion. Text/options/SKUs/prices/variants support reviewed updates. Unknown creates are never retried blindly, even after an absent early lookup. Shared or externally altered media can yield needs-attention; this does not authorize arbitrary file deletion.
