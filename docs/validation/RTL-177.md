## Implementation and researched API

Shopify Admin GraphQL2026-10 documents collection `image` in create/update input and `ImageInput.src` as a URL. Existing `write_products` covers the mutation. The implementation uses `CollectionCreateInput` / `CollectionUpdateInput` and the non-deprecated `collection:` argument; it adds no scope, environment setting, bucket, source asset or upload service. Official references are in the ticket and [operations guide](../operations/SHOPIFY.md#current-local-behavior).

The fixed public source is **`https://tryretailor.com/apple-touch-icon.png`**, alt text **Retailor logo**. The local source PNG was visually inspected: existing navy square, white Retailor cart/R mark. Actual public asset probe outside sandbox returned **HTTP200, image/png,4569 bytes**, PNG signature `[137,80,78,71,13,10,26,10]`, with redirects prohibited. The initial sandbox DNS lookup failed; the approved read-only probe outside sandbox succeeded. No Shopify credentials were used for that probe and no remote media was downloaded into a new artifact.

- New owned collections include the logo in the existing collection-create request.
- Existing owned collections require explicit image-presence metadata. A non-null image is preserved, including an image whose ID is null. Missing/malformed image metadata fails closed rather than being treated as blank.
- When blank, ownership and image are checked again before an id/image-only update. Title, description, products, rules, publications and merchant images are not resent. Handle, app marker and known remote ID remain authoritative; title matching is never ownership.
- A private `imageDispatched` flag defaults false for old ledgers, is persisted before mutation, and prevents blind repeat after unknown/processing outcomes. Observing any image clears that fence. A definite rejection permits a new explicit attempt. A confirmed later removal after a known successful fill can be filled again.
- Both actual product exports and reviewed updates run the check, including a same-fields confirmation that otherwise returns an already-configured draft. Legacy exports with no collection record do not create a new collection during update.
- Connect, browse, Check outcome, health and cleanup do not start brand writes. Existing collection/product removal, image sanitization, expiry, leases, finite shared admission/rates, deadlines, encrypted state and private error/log controls remain.

**API limit:** the documented collection-image update has no atomic only-if-empty condition. We implement a fresh read followed by the guarded update, not remote CAS with simultaneous Shopify-admin edits. An unknown write whose image remains absent is held rather than automatically repeated. Native image processing/appearance and simultaneous external edits are not proven by local fixtures. Shopify/CDN retention is not a physical-erasure claim.
