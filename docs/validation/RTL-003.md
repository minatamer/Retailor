## Pass 1 — read-only review

**Verdict: Does not yet meet ticket.** All fifteen assets exist, the actual sample pipeline runs, and initial gates pass, but recovery/cleanup needs correction before committing.

- **Medium — cleanup truth and async ownership:** `apps/frontend/src/features/photos/controller.ts:332` can publish a late remove-cache failure after a newer reset; `:427` swallows failed reset-cache deletion and still reports complete clearing. Guard notices by operation generation and report incomplete storage cleanup honestly.
- **High — recovery identity:** `controller.ts:339` restores any independently valid cached photo with the requested ID without comparing its source/derivative hashes to persisted session metadata. A replacement whose cache write failed can therefore restore the previous garment under the new selection's identity. Require exact expected descriptors on session recovery, preserve valid in-memory work and reject stale cached bytes.
- **Medium — recovery/expiry envelope:** `controller.ts:127` can report available photos after expiry until the heartbeat clears them; `:339` can merge recovered rows with uncached in-memory entries beyond the 32-source/40-MiB/24-MiB envelope. Recheck availability immediately and enforce the union envelope before decode.
- **Medium — persisted cache counters:** `apps/frontend/src/features/photos/cache.ts:181` uses a replaced persisted row's Blob sizes without validating that row; removal has the same assumption. Validate old rows and resulting counters so corrupt persistence cannot understate the owned byte envelope.
