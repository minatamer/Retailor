## Newly clarified installation UX gap

During this revision the owner clarifies that users should choose their store inside Shopify instead of typing a domain in Retailor. This is a separate unresolved auth-flow requirement; this visual change does not satisfy it or claim generic visitor installability.

Current direct authorization is intentionally shop-specific: `connect` reserves the shop before redirect, the authorization URL contract accepts only that shop's OAuth endpoint, and signed `install` matches an already pending attempt for the same shop. Removing the input or swapping a URL alone cannot safely accept a later Shopify-selected shop. A replacement must bind Shopify's signed install request to the original anonymous cookie/tab attempt, preserve HMAC/state/replay/expiry/shop-conflict/cleanup controls and use an actually supported install entry for the selected distribution.

Rechecked primary sources: [App Store requirement2.3.1](https://shopify.dev/docs/apps/launch/shopify-app-store/app-store-requirements) requires Shopify-owned installation and forbids manually collecting the shop domain for public App Store apps. [Shopify staff, July2026](https://community.shopify.dev/t/shopify-developer-app-flow/36047) describe linking to the listing and letting Shopify select the store. [Shopify staff clarification](https://community.shopify.dev/t/is-there-a-way-to-let-the-user-select-which-store-s-they-want-to-connect-in-my-app/26835) explains there is no supported generic pre-OAuth account/store discovery API for direct third-party OAuth. [Draft-app testing guidance](https://community.shopify.dev/t/identifying-apps-public-listing-link/22425) uses the Dev Dashboard install-on-development-store entry; it does not establish unrelated users can install without review. No internal `/destinations` endpoint, undocumented last-used-store authorization URL, fabricated listing link or owner-org install link is shipped as a generic visitor solution. Distribution selection/review remains owner-controlled.
