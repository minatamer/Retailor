## Confirmed code-quality findings and careful execution

### CQA-01 — unknown technical exceptions can become visitor notices

Evidence: `features/photos/controller.ts` photo-input/selection/repair catches forward `error instanceof Error ? error.message : ...`; catalogue edit review excludes names containing “Zod” but otherwise forwards arbitrary `.message`. Unknown DOM/storage/worker/runtime errors can contain technical instructions or internal values. Photo worker itself already limits raw unknown messages, and API error classes already reconstruct public copy from code; preserve those good controls. CacheConflict and raster failures have intentional local validation/recovery copy and must remain helpful.

Fix: explicit trusted local input/error provenance, source-controlled messages for known invalid money/stock/photo boundaries, generic recovery for all other exceptions. Shared API errors continue rebuilding copy from fixed codes. Move narrow shared error ownership out of catalogue-only coupling if A2 needs it. Inspect actual Next guidance and owned friendly route/global error fallback without console suppression or a new telemetry endpoint. Do not replace all helpful validation with vague failure, alter state transitions, clear valid data, log raw client exceptions or hide diagnostic output.

Check: private marker in arbitrary injected decoder/repair/submit failures never appears in notice/UI; valid input errors remain specific; accepted photos/order/old repair bytes and late/cancel/reset fences retained. Actual fake-mode browser invalid photo/review/recovery plus normal sample/style/order/dashboard path at compact/wide/tablet. Framework/native browser diagnostics are distinct from project-controlled logs; do not promise to erase browser network/compiler diagnostics with an unsafe global patch.

### CQA-02 — repeated chunk arrays and catalogue-specific shared transport errors

Evidence: four real browser requester paths independently read bounded JSON chunks (`catalogue/live-processor.ts`, `assistants/request.ts`, `logos/request.ts`, `currency/request.ts`). Each retains an array then allocates/copies the joined bytes. Empty chunks also create retained entries. Caps/deadlines/public error handling are conceptually the same but ownership is scattered; Tailor/logos import a class named CatalogueRequestError from the catalogue feature.

Fix: one narrow browser response/error owner reused by actual callers, fixed bounded storage and iteration/cancel cleanup; preserve all fetch credentials/method/cache/redirect operations, feature-owned request/SDK limits, dispatch marker, deadlines, schemas and error code/OPERATOR_REQUIRED semantics. Preserve FX's stricter UTF-8 handling. Delete replaced readers and the old error-owner path after updating real/test references; no unused compatibility alias, generic URL fetch or new dependency. Initial allocation may grow to accommodate regression evidence; functionality is the acceptance criterion.

Check: exact-byte cap/segmented read, oversize, absent body, malformed JSON/public envelope, empty chunks, abort/stalled body, release/listener/timeout ownership, preserved source-controlled copy and full catalogue/Tailor/logo/FX requester tests. Report reduced retained buffers from actual design/read behavior; measure only what is actually observed, never fabricate heap/performance numbers. No provider execution or security admission change.

### CQA-03 — two candidate unused runtime schemas

Evidence: AST single-mention scan identifies `HashSchema` in contracts/photos and catalogue-only `AdmissionRequestSchema` in contracts/recognition. All consumers must be checked with source/import/package-reference search before deleting. Current actual admission route owns the catalogue/assistant/logo union and no consumer has yet been found for the old catalogue-only request schema. Photo descriptors already own hash validation elsewhere.

Fix: remove only proven unused runtime definitions, preserving used shape/limits/package exports. Public type aliases (Mode, Category, graph record types, model/export types) are intentionally useful public typing and have no runtime allocation; retain them with rationale. Next GET/POST/pages/layouts are framework entrypoints; retain them. Development design/photo references are explicit useful routes and production-gated, not dead production state. Never treat CSS selectors, dynamic imports, fixtures or public package subpaths as dead from a single textual mention.

Check: zero consumer references confirmed, all strict types/boundaries/tests/build pass, no serialization/API shape or domain rule changes. Record retained candidates and how reachability was established.

### CQA-04 — private request-failure correlation is missing at the Express boundary

Evidence: `http/app.ts` final error middleware computes stable code/status/publicError and ends the response; it has no private request-failure sink. Existing explicit backend startup and bind failure logs remain valuable. Tool/evaluation/release diagnostics are private operator output; frontend project source contains no console calls. SDK privacy settings must not be changed to raw debug output just to add observability.

Fix: narrow injected backend diagnostic port, enabled by explicit startup, for fixed failure event/operation/code/status/request reference and sanitized source locations. Preserve every existing log call and source-controlled public envelope. No raw cause/payload/key/header/query/guest name/photo/prompt/graph logging, no browser telemetry route, no logger service/package and no change to status/admission behavior. Diagnostic sink failure must never prevent the original HTTP response. Factories/imports remain inert and injected tests observe metadata without printing sensitive input.

Check: backend sink receives meaningful fixed metadata; public messages and statuses remain identical; marker-containing error/body/SDK values are absent from both visitor output and diagnostic event; safe source-location correlation works; broken logger is isolated; no error log for healthy/config paths; original log sites stay present. This adds diagnostic continuity rather than silently deleting existing information.

## Executed quality dispositions — 13 October 2026

All four confirmed quality findings are implemented. The raw-error paths use explicit `PhotoInputError`/finite `RasterError` and a private catalogue-input error; unknown DOM/worker/schema exceptions select generic copy. Worker failure envelopes carry finite raster codes. The actual form decoder uses unchanged exact USD parsing, IDs/photo order/options and stock bounds. Next 16.4's installed error-convention documentation was inspected: client `error.tsx` and root `global-error.tsx` use its `retry` prop, share a friendly responsive recovery component and never print/display the error argument. No application console shim/telemetry endpoint or raw log suppression was added.

Catalogue, Tailor, logos and FX now consume `http/response.ts` and `http/api-error.ts`; their fetch/deadline/consent/grant/result/dispatch owners remain with the features. All old `CatalogueRequestError` consumers/tests moved together; the old feature-owned shared error module is deleted. One named-limit buffer replaces retained chunks plus a concatenation buffer; actual-byte and finite-chunk checks, abort/cancel/listener/lock cleanup and safe public codes are shared. FX alone retains fatal UTF-8. Allocation is an envelope reservation, not a claim that every small response uses less memory: the maximum logo backing buffer is 4,404,020 bytes; prior worst-case payload retention required its chunks plus another equally sized joined allocation. No heap or latency benchmark is claimed for this change.

Only unused runtime `HashSchema` and obsolete catalogue-only `AdmissionRequestSchema` were removed. Source/test/script/package-subpath consumer search confirmed zero consumers; executable boundaries/types/tests/build passed. Every intentional public type, framework GET/POST/page/layout, worker `new URL`, development reference, fixture and normal CSS/motion remains. No financial authority, serialized payload, architecture, provider/admission/spend or deployment policy was rewritten.

Backend explicit startup now supplies the narrow `http/diagnostics.ts` sink to the inert HTTP factory. Failures retain stable public codes/status while private stderr receives event/operation/request reference/exception class/source basenames and locations. Exception text, stack first line, full paths, bodies/query/headers/grants/cookies/photos/prompt/model output are excluded. Broken sink behavior cannot replace the original response. Existing startup stdout, fixed bind stderr and all evaluation/release/operator output remain. Both SDK `logLevel: "off"` settings remain unchanged. Project frontend sources have zero technical console calls; native browser HTTP diagnostics, React/Next development overlays and framework diagnostics are separate mechanisms and have not been globally suppressed. This audit does not claim to erase every browser-engine/framework console message.
