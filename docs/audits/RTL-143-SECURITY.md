## SEC-143-02 — fragmented multipart memory amplification, fixed

**Medium availability impact; high confidence in parser behavior. STRIDE: DoS.** `apps/backend/src/catalogue/multipart.ts` previously retained a `Buffer[]` for each file and concatenated it at completion. Payload byte caps did not cap retained fragment-object/list overhead. An admitted caller whose fragmentation survives transport can submit many tiny chunks within the19MiB request/18MiB derivative envelope, growing memory before the native RSS gate. Existing origin/private-backend/admission, two shared leases, finite attempts and120-second deadline restrict prerequisites; unauthenticated direct-provider access is not claimed.

Safe independent reproduction: a128KiB injected multipart file in one-byte fragments retained131,072 buffer references before concatenation, returned exact bytes and released the lease. No socket, provider or allocation-exhaustion attack was used. Whole-public-ingress exploitation and an actual OOM were deliberately not attempted.

Remedy: after grant/manifest validation, allocate one buffer of the admitted file size (≤768KiB) and copy incoming bytes into it. The manifest's aggregate≤18MiB bound caps total retained file payload independently of fragmentation. Check actual count/transport/aggregate as before; incomplete/truncated files fail before publication, so zero-filled padding cannot become input. File count/coverage, parser backpressure, native sanitizer/hash checks, deadlines, replay, cancellation and all private logs remain.

The same resource probe now retains no chunk list and returns identical bytes with zero active leases afterward. A functional regression covers byte-fragmented accepted contents and cancellation of a partially received file; existing maximum-file,24-file, transport, malformed/order/replay and actual native sample tests remain. No implementation-shape-only assertion is added. Early mutable-buffer test harnesses violated streaming ownership before Busboy delivered data; those harnesses were corrected, not treated as product evidence.

One existing giant-upload test assumed bounded rejection always yields413. Under overlapping heavy checks it instead received `ECONNRESET`, an allowed consequence of deliberately closing an incomplete rejected tail. It now accepts only413 or that explicit socket-reset code, still requires no provider dispatch/active lease, and still independently verifies per-file413/streamed transport caps. Product draining/limits/timeouts were not relaxed.

Rollback: revert parser/test group together if a real upload regression appears; restore neither unlimited buffering nor larger limits as a workaround. Current complete decode/native admission and photo identity behavior must remain.
