## SEC-195-01 — Outdated Node security baseline

**Priority: update before release; vendor High issues present, application exploitability not demonstrated.** Both Dockerfiles pin Node24.21.0 and the same13October base digest. Actual runtime inspection confirms Node24.21.0, Brotli1.2.0, Undici7.29.1 and OpenSSL3.5.8. The [21October security release](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) fixes issues affecting24.x, including Brotli memory corruption and DNS/TLS handling. Today's [11November release](https://nodejs.org/en/blog/vulnerability/november-2026-security-releases) adds HTTP/2/TLS and dependency fixes; the official [release index](https://nodejs.org/dist/index.json) now lists24.22.3 as a security release. The primary November notice/index were downloaded directly when the search renderer could not fetch their fresh contents.

Applicability: Retailor's backend listens with cleartext HTTP, and the frontend standalone server is also reached through Cloud Run's TLS termination. No application HTTP/2 server, per-host mTLS policy, permission-model sandbox or user-land startup snapshot was found. Request compression is rejected before parsing; Shopify JSON explicitly requests identity encoding and rejects compressed responses. Outbound fetches still use the runtime, including authenticated Shopify CDN photo imports and fixed provider endpoints. These restrictions reduce specific attack paths; they do not establish that an old runtime or every bundled dependency is safe. No exploit payload was sent to a running service and no compromise is alleged.

Disposition: replace the exact official Node24 Bookworm slim pin with a verified24.22.3-or-newer24.x security image, preserve the distro/runtime user/commands and deployment settings, then rebuild both images and rerun actual native/runtime/asset/source-proof checks. Obtain the registry digest from the official image metadata; do not invent one. Refresh the advisory evidence against the rebuilt images. Do not merely change documentation to label the existing images patched.

## SEC-195-02 — APT build-time supply-chain exposure

**Conditional build-time finding; no website exploit demonstrated.** Installed APT2.6.1 is below Bookworm's2.6.2 fix for [CVE-2026-109518](https://security-tracker.debian.org/tracker/CVE-2026-109518). The tracker describes an on-path/mirror attacker exploiting redirects/retries to substitute a package. Both Dockerfiles run APT as root during image construction. Actual image sources use HTTP Debian URLs; no explicit Acquire::Retries override was returned by `apt-config`. That observation does not independently prove every exploit prerequisite or effective compiled retry default. Runtime UID1000 and lack of an application package-install endpoint bound the live website path.

Disposition: when refreshing the official base, verify installed APT is at least2.6.2 before relying on it for package installation; preserve supported Bookworm packages and check any existing Perl pin against the refreshed vendor package. If a retained older base needs repair, use the supported vendor procedure with authenticated transport and no affected retry path, rather than an unauthenticated fetch of an arbitrary replacement binary. Rebuild/probe before release. No arbitrary distro migration, package stripping or scanner suppression is justified by this finding.

## Required hosted gates and release decision

Keep the existing domain/services/limits/paid master/secret bindings intact. The owner confirmed the two secret values; payloads remain unread. Before public Shopify use, verify the dedicated bucket/CAS/retention and actual least-privilege access, real Scheduler OIDC/heartbeat and anonymous denial, scoped exclusion of sensitive install/callback request URLs, and Shopify's published hosted URLs/lifecycle webhooks. Then test actual consent/read/import/reviewed photo export/update/remove/disconnect/expiry and Stripe/live-AI behavior under the existing authorization. Account login/URL change is still deferred by the owner. Outside-organization store eligibility remains unverified and owner-accepted; no App Store review or universal-install claim is added.

The new findings call for exact-image maintenance and renewed proof before cutover. They do not justify redesigning OAuth, asking every merchant for API keys, exposing the backend, adding a database/service, changing the domain or requiring Docker Scout authentication. No production compromise was observed or tested for. Findings and pending gates remain explicit until actual execution evidence closes them.
